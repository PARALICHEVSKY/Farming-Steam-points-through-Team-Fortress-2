# Farming-Steam-points-through-Team-Fortress-2

**Farming Steam Points through Team Fortress 2**: buy Mann Co. Supply Crate Keys in TF2's in-game store to earn Steam Points, then sell the keys on the Steam Community Market to recover part of the cost as Steam Wallet funds. Repeat the cycle to accumulate points while tracking the loss on each key.

Скрипт на Node.js, который автоматизирует этот цикл:

1. Входит в Steam (коды Steam Guard генерируются из `shared_secret`).
2. Подключается к координатору TF2 и покупает ключи в магазине Манн Ко. Покупка идёт с кошелька Steam, поэтому за неё начисляются очки Steam.
3. Подтверждает транзакцию через веб-сессию магазина, как это делает оверлей Steam.
4. Ждёт, пока ключи появятся в инвентаре и станут доступны для продажи.
5. Выставляет их на Торговую площадку по **текущей минимальной цене продажи** (или на `UNDERCUT` дешевле).
6. Автоматически подтверждает лоты через мобильный аутентификатор (`identity_secret`). Подтверждаются **только лоты ТП**, обмены скрипт не трогает.
7. Записывает каждую покупку и продажу в журнал `data/ledger.json` и считает убыток на ключ и цену 100 очков.

> ⚠️ **Важно**
> - Скрипт тратит **реальные деньги**. По умолчанию включён `DRY_RUN=true`: скрипт только показывает, что сделал бы. Отключайте его, только когда проверите цены командой `price`.
> - Каждый цикл убыточен: ТП берёт ~15% комиссии (5% Steam + 10% TF2), и ключ на ТП обычно дешевле, чем в магазине. Очки получаются за счёт этого убытка. Скрипт показывает, сколько стоит 100 очков.
> - Автоматизация может нарушать Соглашение подписчика Steam. Вы используете её на свой риск.
> - `.env` и папка `data/` (там хранится токен входа) содержат доступ к аккаунту. Никому их не передавайте. Оба пути уже в `.gitignore`.

## Требования

- Node.js 18+
- Мобильный аутентификатор Steam, перенесённый в [Steam Desktop Authenticator](https://github.com/Jessecar96/SteamDesktopAuthenticator) (или аналог), чтобы получить `shared_secret` и `identity_secret` из maFile.
- Аутентификатор должен быть включён не меньше 7 дней, иначе Steam придерживает лоты на ТП.
- Деньги в кошельке Steam.

## Установка

```bash
npm install
cp .env.example .env
# заполните .env: логин, пароль, shared_secret, identity_secret
```

Цена ключа в магазине нужна в валюте вашего кошелька, в минимальных единицах (центы/копейки):

- либо впишите её сами в `KEY_STORE_PRICE` (например `249` для $2.49; посмотрите цену в магазине Манн Ко. в игре);
- либо задайте `STEAM_API_KEY`, и цена будет взята из `ISteamEconomy/GetAssetPrices`.

Если цена не совпадёт с ценой магазина, координатор TF2 отклонит покупку (`InvalidParam`/`WrongCurrency`), и деньги не спишутся.

## Использование

```bash
npm run price                      # цены сейчас и убыток на ключ, ничего не покупает
npm run run-cycle -- --keys 2 --cycles 3   # 3 цикла по 2 ключа
npm run buy -- --keys 1            # только купить
npm run sell                       # выставить купленные ключи по мин. цене и подтвердить
npm run confirm                    # подтвердить висящие лоты ТП
npm run stats                      # статистика из журнала
npm run dashboard                  # веб-дашборд на http://localhost:3000
```

Пример вывода `price`:

```
Магазин TF2: 2.49 USD | ТП мин. цена продажи: 2.30 USD | макс. заявка на покупку: 2.21 USD
Выставим за 2.30 USD -> получим 2.00 USD | убыток 0.49 USD (19.7%) | ~249 очков | 0.20 USD за 100 очков
```

## Защитные настройки (`.env`)

| Параметр | Что делает |
|---|---|
| `DRY_RUN` | `true`: ничего не покупать и не выставлять |
| `MAX_LOSS_PERCENT` | цикл пропускается, если убыток на ключ больше этого процента |
| `DAILY_SPEND_LIMIT` | лимит трат в магазине за сутки (минимальные единицы валюты) |
| `MIN_BUYER_PRICE` | не выставлять дешевле этой цены |
| `SELL_ONLY_PURCHASED` | продавать только ключи, купленные скриптом; уже лежащие в инвентаре ключи не трогать |
| `UNDERCUT` | на сколько дешевле минимального лота выставлять |
| `POINTS_PER_UNIT` | очков за 1 единицу валюты (100 за $1). Используется только для оценки |

Перед каждой покупкой скрипт также проверяет баланс кошелька. Деньги от проданных ключей приходят только после того, как кто-то купит лот, поэтому следующий цикл может ждать пополнения.

## Как это устроено

| Файл | Назначение |
|---|---|
| `src/steam.js` | вход (`steam-user`), Steam Guard, веб-cookies, кошелёк |
| `src/gc.js` | минимальный клиент координатора TF2 (protobuf) |
| `src/store.js` | покупка в магазине Манн Ко.: `StorePurchaseInit` → подтверждение транзакции → `StorePurchaseFinalize` |
| `src/market.js` | цены ТП (`itemordershistogram`), инвентарь, `market/sellitem` |
| `src/fees.js` | расчёт комиссий ТП (цена покупателя ↔ сколько получит продавец) |
| `src/confirm.js` | мобильные подтверждения лотов (`identity_secret`) |
| `src/ledger.js` | журнал и статистика |
| `src/dashboard.js` | локальный дашборд |

Если транзакцию не удалось подтвердить автоматически, скрипт выведет ссылку `store.steampowered.com/checkout/approvetxn/...`. Её можно открыть и подтвердить вручную в течение `MANUAL_APPROVE_WAIT_MINUTES` минут. Если подтверждения не будет, транзакция отменится.

## Ограничения

- Журнал хранит **ожидаемую** выручку по цене выставления. Если лот провисит долго и цена изменится, реальная выручка может отличаться.
- Если Steam наложит на купленные ключи запрет на продажу, `run` дождётся `INVENTORY_WAIT_MINUTES`, а потом их можно будет продать позже командой `sell`.
